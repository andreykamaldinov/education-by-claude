Браузер умеет загружать ES-модули напрямую. Зачем тогда сборщик? Потому что исходный код проекта — это тысячи файлов на TypeScript, импорты npm-пакетов по имени, шаблоны, Sass, изображения. Сборщик превращает всё это в небольшое число оптимизированных файлов, которые быстро загружаются.

## Что делает сборщик

### 1. Строит граф модулей

Начиная с **точки входа** (`main.ts`), сборщик читает импорты, находит файлы (в том числе в `node_modules` по правилам разрешения модулей) и строит граф зависимостей.

```text
main.ts
 ├── app.config.ts ──▶ @angular/router, @angular/common/http
 ├── app.ts ──▶ site-header.ts ──▶ icon.ts
 └── (import())  home-page.ts ──▶ track-shelf.ts     ← динамический импорт = отдельный чанк
```

### 2. Трансформирует файлы

- TypeScript → JavaScript, понижение синтаксиса под целевые браузеры.
- Шаблоны Angular → инструкции (через компилятор Angular).
- Sass/Less → CSS, PostCSS (Tailwind, автопрефиксы).
- Импорты ресурсов (изображения, шрифты, JSON, текст) → URL или содержимое.

Инструменты для этого называются loaders (Webpack) или plugins (esbuild, Rollup, Vite).

### 3. Бандлинг

Объединение многих модулей в немногие файлы (чанки). Даже с HTTP/2 тысячи мелких файлов загружаются медленнее: каждый — отдельный запрос, а цепочки импортов создают «водопад» загрузки.

### 4. Tree-shaking

Удаление неиспользуемого кода на основе статического анализа ESM-импортов:

```ts
// utils.ts
export const used = () => 'нужно';
export const unused = () => 'не попадёт в бандл';

// main.ts
import { used } from './utils';
```

Работает только с ESM (статическая структура `import`/`export`), мешают побочные эффекты на верхнем уровне модулей. Пакеты помечают отсутствие эффектов полем `"sideEffects": false` в `package.json`.

### 5. Code splitting

Разделение кода на чанки, загружаемые по требованию:

- **По точкам динамического импорта** — `import()` в ленивых маршрутах и `@defer`.
- **Общие чанки** — код, используемый несколькими ленивыми частями, выносится отдельно, чтобы не дублироваться.
- **Vendor-чанки** — зависимости отдельно от кода приложения (реже меняются → дольше в кеше).

### 6. Минификация и оптимизация

- Удаление пробелов и комментариев, сокращение имён переменных.
- Удаление мёртвого кода (`if (false)`), свёртка констант, встраивание (inlining).
- Минификация CSS, удаление неиспользуемых стилей (критический CSS).

### 7. Хеширование имён

`main-2LXTBFJM.js` — хеш от содержимого. Файл можно кешировать «навсегда» (`Cache-Control: immutable`), а при изменении кода имя изменится, и браузер загрузит новую версию.

### 8. Source maps

Карты соответствия минифицированного кода исходному — для отладки и для трекеров ошибок (Sentry). В production их обычно не публикуют, а загружают в систему мониторинга.

## Dev и production

| | Разработка | Production |
| --- | --- | --- |
| Цель | быстрый старт и мгновенные пересборки | минимальный размер и быстрая загрузка |
| Минификация | нет | да |
| Source maps | полные | скрыты или отключены |
| Обновление | HMR — горячая замена модулей без перезагрузки | — |
| Проверки | dev-mode проверки Angular | удалены (tree-shaking `ngDevMode`) |

## Эволюция инструментов

| Поколение | Инструменты | Идея |
| --- | --- | --- |
| Таск-раннеры | Grunt, Gulp | конвейеры над файлами |
| JS-бандлеры | Browserify, Webpack, Rollup, Parcel | граф модулей, всё — модуль |
| Нативные инструменты | esbuild (Go), SWC (Rust), Rspack (Rust), Rolldown (Rust), Turbopack | скорость за счёт компилируемых языков и параллелизма |
| Dev на нативных ESM | Vite, Snowpack (устарел) | в разработке не собирать бандл, отдавать модули браузеру |

Angular прошёл этот путь: Webpack → esbuild + Vite ([Почему Angular перешёл на esbuild и Vite](/tracks/tooling/angular-builders)).

> [!INTERVIEW]
> «Что такое tree-shaking и почему он иногда не работает?» — Удаление неиспользуемых экспортов на основе статического анализа ES-модулей. Не работает или работает плохо, если зависимость в формате CommonJS, если модули имеют побочные эффекты на верхнем уровне (и не помечены `sideEffects: false`), если импортируется весь пакет (`import * as _` / default-объект) или код использует динамический доступ к экспортам.

## Коротко

- Сборщик строит граф модулей от точки входа и трансформирует файлы.
- Бандлинг, tree-shaking, code splitting, минификация, хеширование, source maps.
- Tree-shaking требует ESM и отсутствия побочных эффектов.
- `import()` создаёт отдельные чанки — основа ленивой загрузки.
- Современные инструменты написаны на Go и Rust ради скорости.
