Замыкание — это функция вместе с лексическим окружением, в котором она была создана. Звучит академично, но на практике это самый частый механизм в JavaScript: на нём построены приватное состояние, фабрики функций, мемоизация, debounce, обработчики событий и половина операторов RxJS.

## Лексическое окружение

Каждый раз, когда выполняется функция (или блок `{ }` с `let`/`const`), движок создаёт **лексическое окружение** — объект, где лежат локальные переменные, и ссылка на внешнее окружение. Цепочка таких ссылок и есть «область видимости».

```js
const greeting = 'Привет';

function makeGreeter(name) {
  // окружение makeGreeter: { name }  →  внешнее: { greeting, makeGreeter }
  return function greet() {
    // окружение greet: {}  →  makeGreeter  →  глобальное
    return `${greeting}, ${name}!`;
  };
}

const greetAnna = makeGreeter('Анна');
greetAnna(); // 'Привет, Анна!'
```

`makeGreeter` уже завершилась, но `greet` по-прежнему видит `name`. Функция хранит скрытую ссылку `[[Environment]]` на окружение, где её создали, и сборщик мусора не удалит это окружение, пока жива сама функция.

> [!NOTE]
> Замыкание фиксирует **ссылку на переменную**, а не её значение в момент создания. Если переменная изменится, функция увидит новое значение.

## Приватное состояние

До появления `#private` полей замыкания были единственным способом спрятать данные. Этот приём до сих пор встречается в библиотеках и в функциональном коде.

```ts
function createCounter(initial = 0) {
  let count = initial; // недоступна снаружи

  return {
    increment: () => ++count,
    decrement: () => --count,
    get value() {
      return count;
    },
  };
}

const counter = createCounter(10);
counter.increment(); // 11
counter.value; // 11
// counter.count — undefined: доступа к переменной нет
```

Каждый вызов `createCounter` создаёт новое окружение, поэтому два счётчика полностью независимы.

## Фабрики и частичное применение

Замыкание позволяет «запомнить» часть аргументов и вернуть специализированную функцию:

```ts
const multiplyBy = (factor: number) => (value: number) => value * factor;

const double = multiplyBy(2);
const triple = multiplyBy(3);

[1, 2, 3].map(double); // [2, 4, 6]
```

Этот же принцип лежит в основе каррирования и операторов RxJS: `map(fn)` возвращает функцию, которая замыкает `fn` и применяет её к каждому значению потока.

## Классическая ловушка: замыкание в цикле

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3, 3, 3
```

`var` объявляет **одну** переменную на всю функцию. Все три стрелки замыкают одну и ту же `i`, а к моменту срабатывания таймеров цикл уже закончился.

С `let` каждая итерация получает собственную привязку:

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 0, 1, 2
```

> [!INTERVIEW]
> «Что выведет код с `var` в цикле и как это исправить?» — Ответ: `3, 3, 3`, потому что все колбэки замыкают одну переменную. Исправления: заменить `var` на `let`, либо создать отдельную область видимости через IIFE `((j) => setTimeout(() => console.log(j)))(i)`, либо передать значение третьим аргументом `setTimeout(console.log, 0, i)`.

## Мемоизация

Замыкание — удобное место для кеша, который не виден снаружи:

```ts
function memoize<A extends string | number, R>(fn: (arg: A) => R): (arg: A) => R {
  const cache = new Map<A, R>();
  return (arg) => {
    if (cache.has(arg)) {
      return cache.get(arg)!;
    }
    const result = fn(arg);
    cache.set(arg, result);
    return result;
  };
}

const slowSquare = (n: number) => {
  for (let i = 0; i < 1e7; i++) {} // имитация тяжёлой работы
  return n * n;
};

const fastSquare = memoize(slowSquare);
fastSquare(9); // считает
fastSquare(9); // берёт из кеша
```

## debounce своими руками

Одна из самых частых задач на собеседовании. Таймер живёт в замыкании и переживает вызовы:

```ts
function debounce<Args extends unknown[]>(fn: (...args: Args) => void, ms: number) {
  let timer: ReturnType<typeof setTimeout> | undefined;

  return (...args: Args): void => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), ms);
  };
}

const search = debounce((query: string) => console.log('Ищем', query), 300);
search('a');
search('an');
search('ang'); // через 300 мс выполнится только этот вызов
```

В Angular ту же задачу обычно решают оператором `debounceTime` из RxJS, но понимать ручную реализацию полезно — именно её просят написать на интервью. Попробуйте в [практике](/practice/js-debounce).

## Замыкания и память

Пока функция достижима, достижимо и всё её окружение. Отсюда типичная утечка:

```ts
function attachHandler(element: HTMLElement) {
  const hugeReport = buildReport(); // десятки мегабайт

  element.addEventListener('click', () => {
    console.log('clicked'); // hugeReport не используется...
  });
}
```

Современные движки (V8) умеют не удерживать переменные, которые замыкание не использует, но если хотя бы одна функция из того же окружения обращается к `hugeReport`, его будут держать все. Правило простое: снимайте обработчики и подписки, когда компонент уничтожается, и не храните в замыканиях больше, чем нужно. Подробнее — в уроке [о памяти и сборке мусора](/tracks/javascript/memory-gc).

> [!WARNING]
> В Angular-компонентах подписка RxJS в `ngOnInit` без отписки — это замыкание, которое держит компонент в памяти после его уничтожения. Используйте `takeUntilDestroyed()` или `async` pipe.

## Где замыкания встречаются в Angular

| Место | Что замыкается |
| --- | --- |
| `inject()` в фабрике провайдера | контекст инжектора в момент вызова |
| Функциональные guards и interceptors | зависимости, полученные через `inject()` |
| `computed(() => ...)` | сигналы, которые читаются внутри |
| Операторы RxJS: `map`, `filter`, `switchMap` | функции-проекторы и их окружение |
| Обработчики в шаблоне `(click)="save(item)"` | переменная `item` из `@for` |

## Коротко

- Замыкание — функция плюс ссылка на окружение, где она создана.
- Замыкается переменная, а не значение: изменения видны.
- Используется для приватного состояния, фабрик, мемоизации, debounce/throttle.
- `var` в цикле — одна переменная на все итерации, `let` — новая на каждую.
- Окружение живёт, пока жива функция: следите за подписками и обработчиками.
