Помимо SOLID есть короткие принципы, на которые постоянно ссылаются на код-ревью. Они звучат очевидно, но применять их нужно с пониманием: доведённые до абсолюта, они противоречат друг другу.

## DRY — Don't Repeat Yourself

> Каждый фрагмент **знания** должен иметь единственное, однозначное, авторитетное представление в системе.

Ключевое слово — **знание**, а не «текст». DRY — о том, чтобы бизнес-правило, константа или формат жили в одном месте.

```ts
// Нарушение: правило «минимальная длина пароля» в трёх местах
// form: Validators.minLength(8)
// подсказка в шаблоне: «не менее 8 символов»
// сервер: if (password.length < 8)

// Одно место знания
export const PASSWORD_MIN_LENGTH = 8;
Validators.minLength(PASSWORD_MIN_LENGTH);
`Не менее ${PASSWORD_MIN_LENGTH} символов`;
```

В TypeScript DRY относится и к типам: выводите типы из одного источника (`as const`, `typeof`, `Pick`, схемы), а не копируйте вручную.

### Ложное дублирование

```ts
const isAdult = (user: User) => user.age >= 18;
const canBuyAlcohol = (user: User) => user.age >= 18;
```

Код совпадает, но знание разное: возраст совершеннолетия и закон о продаже алкоголя меняются по разным причинам и в разных странах — по-разному. Объединив их, вы свяжете то, что должно меняться независимо.

> [!TIP]
> Правило трёх: впервые пишите, на второй раз — заметьте дублирование, на третий — выносите. Преждевременная абстракция обходится дороже, чем дублирование: «duplication is far cheaper than the wrong abstraction» (Сэнди Метц).

## KISS — Keep It Simple

Простое решение, которое понятно следующему разработчику, лучше умного.

```ts
// «Умно»
const unique = [...new Map(items.map((i) => [i.id, i])).values()].sort((a, b) => +(a.name > b.name) || -(a.name < b.name));

// Просто
const byId = new Map(items.map((item) => [item.id, item]));
const unique = [...byId.values()].toSorted((a, b) => a.name.localeCompare(b.name));
```

Признаки нарушения KISS в Angular:

- NgRx с эффектами для формы из двух полей;
- generic-компонент «для всех будущих таблиц» с тридцатью inputs;
- RxJS-цепочка из 15 операторов там, где хватит `computed`;
- собственный фреймворк поверх Angular.

## YAGNI — You Aren't Gonna Need It

Не реализуйте функциональность, пока она не нужна. Предполагаемые требования часто не наступают, а если наступают — выглядят иначе, чем вы представляли.

```ts
// YAGNI: поддержка 5 провайдеров оплаты, когда используется один
export abstract class PaymentProviderFactoryRegistry { /* ... */ }
```

Но YAGNI не отменяет инженерной гигиены: тесты, типы, разумную структуру и точки расширения там, где изменения **уже** очевидны.

## Закон Деметры (Law of Demeter)

«Разговаривай только с ближайшими друзьями»: метод вызывает методы своего объекта, параметров, созданных им объектов и полей — но не «друзей друзей».

```ts
// Нарушение — «цепочка вагонов» (train wreck)
const city = order.getCustomer().getAddress().getCity().getName();

// Лучше: попросить объект, который владеет знанием
const city2 = order.deliveryCityName();
```

Длинные цепочки связывают код со структурой чужих объектов: изменение `Address` ломает код заказа. Для простых структур данных (DTO, состояние) цепочки доступа к полям допустимы — закон касается объектов с поведением.

## Tell, Don't Ask

```ts
// Ask: вытаскиваем данные и решаем за объект
if (cart.items.length > 0 && cart.total > MIN_ORDER) {
  cart.status = 'ready';
}

// Tell: просим объект сделать то, что он знает лучше
cart.markReadyIfValid();
```

## Принцип наименьшего удивления

Код должен вести себя так, как ожидает читатель. Геттер не делает HTTP-запросов, метод `getUser` не создаёт пользователя, `isValid()` не меняет состояние, сервис с именем `Logger` не отправляет аналитику.

## Конфликты принципов

| Конфликт | Как решать |
| --- | --- |
| DRY против KISS | лишняя абстракция ради устранения двух повторов — хуже повтора |
| DRY против SRP | общий код, меняющийся по разным причинам, — разделите |
| YAGNI против OCP | точку расширения добавляйте, когда ось изменений подтверждена |

> [!INTERVIEW]
> «Всегда ли нужно устранять дублирование?» — Нет. DRY относится к дублированию знания, а не кода. Если два фрагмента совпадают случайно и меняются по разным причинам, их объединение создаёт вредную связь. Часто применяют правило трёх: абстрагировать после третьего повторения, когда понятно, что именно общее. Неправильная абстракция дороже дублирования.

## Коротко

- DRY — одно место для каждого знания; совпадение кода ≠ дублирование знания.
- KISS — понятное решение лучше умного.
- YAGNI — не стройте то, что не нужно сейчас.
- Закон Деметры и Tell, Don't Ask — меньше знания о чужих внутренностях.
- Принципы конфликтуют — решает здравый смысл и причины изменений.
