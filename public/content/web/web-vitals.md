Core Web Vitals — три метрики Google, которые описывают пользовательский опыт: как быстро виден основной контент, как быстро страница реагирует и насколько она стабильна. Они влияют на ранжирование в поиске и — что важнее — на конверсию.

## Три метрики

| Метрика | Что измеряет | Хорошо | Плохо |
| --- | --- | --- | --- |
| **LCP** — Largest Contentful Paint | когда отрисован самый крупный элемент (изображение, блок текста) | ≤ 2,5 с | > 4 с |
| **INP** — Interaction to Next Paint | задержка от действия (клик, ввод) до следующей отрисовки, по худшим взаимодействиям за визит | ≤ 200 мс | > 500 мс |
| **CLS** — Cumulative Layout Shift | суммарные неожиданные сдвиги макета | ≤ 0,1 | > 0,25 |

Оценка ведётся по **75-му перцентилю** реальных пользователей (данные Chrome UX Report). INP заменил FID в 2024 году: FID учитывал только задержку перед обработкой первого взаимодействия, INP — полную задержку всех взаимодействий.

Вспомогательные метрики: **TTFB** (время до первого байта ответа сервера), **FCP** (первая отрисовка любого контента), **TBT** (суммарное время блокировки главного потока в лаборатории).

## LCP: как улучшить

LCP состоит из четырёх частей: TTFB → задержка начала загрузки ресурса → время загрузки → задержка отрисовки.

- **SSR или prerender** — контент в HTML сразу, без ожидания JS ([SSR и гидрация](/tracks/angular/ssr-hydration)).
- **LCP-изображение** — с приоритетом и без ленивой загрузки:

```html
<img ngSrc="/hero.avif" width="1200" height="600" priority />
```

- Современные форматы (AVIF, WebP), правильный размер (`srcset`/`sizes`), CDN.
- Не скрывать основной контент за загрузкой JS (спиннер вместо контента — плохой LCP).
- Шрифты: `font-display: swap`, локальный хостинг, preload основного начертания.
- Меньше initial bundle: ленивые маршруты, `@defer`.

## INP: как улучшить

INP плохой, когда главный поток занят в момент взаимодействия или обработка события сама по себе долгая.

```text
Взаимодействие → [input delay: поток занят] → [processing: обработчики] → [presentation: стили, layout, paint] → кадр
```

- Дробить длинные задачи (> 50 мс): `await scheduler.yield()`, `setTimeout(0)`, вынос в Web Worker.
- Минимизировать работу в обработчиках: сначала обновить UI (показать нажатие), потом тяжёлое.
- В Angular: OnPush и сигналы (меньше компонентов проверяется на каждое событие), `track` в `@for`, виртуальный скролл для больших списков.
- Не запускать дорогие проверки на `mousemove`/`scroll` — throttle или вне шаблона.
- Аккуратнее со сторонними скриптами (чаты, аналитика, A/B), которые занимают главный поток.

```ts
async function onFilterChange(filter: Filter) {
  this.filter.set(filter); // мгновенный отклик UI
  await yieldToMain(); // дать браузеру отрисовать кадр
  this.heavyRecalculate(); // тяжёлое — после
}

const yieldToMain = () =>
  'scheduler' in globalThis && 'yield' in scheduler ? scheduler.yield() : new Promise((r) => setTimeout(r, 0));
```

## CLS: как улучшить

Сдвиг считается, когда видимый элемент меняет позицию без действия пользователя.

- **Размеры у изображений и видео**: `width`/`height` или `aspect-ratio`. `NgOptimizedImage` требует их обязательно.
- **Резервировать место** под рекламу, баннеры, встраиваемые виджеты, ленивые блоки (`@defer` с плейсхолдером той же высоты).
- **Не вставлять контент над существующим** (баннер cookie сверху, уведомления, сдвигающие страницу) — используйте оверлеи.
- **Шрифты**: `size-adjust` и подобранный fallback-шрифт, чтобы смена шрифта не меняла высоту строк.
- Анимации — через `transform`, а не `top`/`height`.

## Как измерять

**Лабораторные данные** (синтетика, один запуск): Lighthouse, PageSpeed Insights (lab), DevTools Performance. Полезны для отладки, но не отражают реальных пользователей и не измеряют INP (только косвенно через TBT).

**Полевые данные (RUM)**: Chrome UX Report, PageSpeed Insights (field), собственный сбор:

```ts
import { onCLS, onINP, onLCP } from 'web-vitals';

const send = (metric: { name: string; value: number; id: string }) =>
  navigator.sendBeacon('/analytics/vitals', JSON.stringify(metric));

onLCP(send);
onINP(send);
onCLS(send);
```

`sendBeacon` гарантирует отправку даже при закрытии вкладки.

> [!TIP]
> Атрибуция: `web-vitals/attribution` показывает, какой элемент был LCP, какое взаимодействие дало плохой INP и что сдвинулось при CLS. Без этого оптимизация превращается в угадывание.

> [!INTERVIEW]
> «Что такое Core Web Vitals и как вы их улучшали?» — LCP (скорость отображения основного контента, ≤ 2,5 с), INP (отзывчивость на взаимодействия, ≤ 200 мс), CLS (визуальная стабильность, ≤ 0,1), оцениваются по 75-му перцентилю реальных пользователей. LCP улучшают SSR, приоритетная загрузка главного изображения и меньший начальный бандл; INP — дробление длинных задач, лёгкие обработчики, OnPush/сигналы и виртуализация; CLS — заданные размеры медиа и зарезервированное место для динамического контента.

## Коротко

- LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 — по 75-му перцентилю.
- LCP: SSR, `priority` для главного изображения, меньше JS до первого экрана.
- INP: длинные задачи дробить, обработчики облегчать, проверок меньше.
- CLS: размеры медиа, место под динамический контент, анимации через `transform`.
- Лаборатория для отладки, полевые данные — для правды.
