Комбинирующие операторы объединяют несколько потоков в один. Главное — понимать, **когда** результат выдаёт значение и **когда** завершается. От этого зависит, увидит ли пользователь данные или будет вечный спиннер.

## combineLatest: последние значения всех

Выдаёт массив последних значений, когда **любой** источник выдаёт новое — но только после того, как **каждый** источник выдал хотя бы одно.

```text
a$:   --a1--------a2-------|
b$:   -----b1--b2------b3--|
combineLatest([a$, b$])
      -----[a1,b1]-[a1,b2]-[a2,b2]-[a2,b3]|
```

```ts
const vm$ = combineLatest({
  user: this.user$,
  settings: this.settings$,
  filter: this.filter$.pipe(startWith('all')),
}).pipe(map(({ user, settings, filter }) => buildViewModel(user, settings, filter)));
```

**Когда**: производное состояние из нескольких источников (фильтры + данные + настройки).

> [!WARNING]
> Если один из источников ещё ничего не выдал, `combineLatest` молчит. Частая причина «ничего не отображается» — поток без начального значения. Добавьте `startWith` или используйте `BehaviorSubject`.

В Angular с сигналами многие `combineLatest` превращаются в обычный `computed(() => build(user(), settings(), filter()))`.

## forkJoin: дождаться завершения всех

Ждёт, пока **все** источники завершатся, и выдаёт их **последние** значения один раз.

```text
a$:   --a1--a2|
b$:   -----b1-----b2|
forkJoin([a$, b$])
      ------------[a2,b2]|
```

```ts
forkJoin({
  user: this.api.user(id),
  orders: this.api.orders(id),
  addresses: this.api.addresses(id),
}).subscribe(({ user, orders, addresses }) => ...);
```

**Когда**: несколько параллельных HTTP-запросов, нужны все результаты — аналог `Promise.all`.

> [!WARNING]
> `forkJoin` с бесконечным потоком (`interval`, `valueChanges`, `BehaviorSubject`) никогда не выдаст значение. Если любой источник упадёт — упадёт весь `forkJoin`, а результаты остальных потеряются. Если источник завершится без значений — `forkJoin` завершится без значений.

Чтобы получить частичные результаты при ошибках:

```ts
forkJoin(ids.map((id) => this.api.load(id).pipe(catchError(() => of(null)))));
```

## zip: попарно по индексу

```text
a$:   --1---2---3|
b$:   ----a-------b---c|
zip(a$, b$)
      ----[1,a]---[2,b]-[3,c]|
```

Ждёт, пока у каждого источника появится N-е значение. Применяется редко: синхронизация пар «запрос — ответ», анимация по кадрам. Опасность — бесконечный буфер, если один поток быстрее другого.

## withLatestFrom: взять текущее значение другого потока

```ts
saveClick$.pipe(
  withLatestFrom(this.form$, this.user$),
  exhaustMap(([, form, user]) => this.api.save({ ...form, ownerId: user.id })),
);
```

Выдаёт значение **только когда выдаёт основной поток**, прихватывая последние значения остальных. В отличие от `combineLatest`, изменения второстепенных потоков сами по себе ничего не запускают.

**Когда**: действие пользователя + текущее состояние.

## merge: объединить события

```text
a$:  --a---a------|
b$:  ----b-----b--|
merge(a$, b$)
     --a-b-a---b--|
```

```ts
const refresh$ = merge(
  fromEvent(refreshButton, 'click'),
  interval(60_000),
  this.visibility$.pipe(filter((visible) => visible)),
);
refresh$.pipe(exhaustMap(() => this.api.load()));
```

**Когда**: несколько источников одного и того же события. Завершается, когда завершатся все.

## concat: строго по очереди

```ts
concat(
  of({ status: 'loading' as const }),
  this.api.load().pipe(map((data) => ({ status: 'success' as const, data }))),
);
```

Подписывается на следующий поток только после завершения предыдущего.

## race: кто первый

```ts
race(this.api.fromPrimary(), this.api.fromMirror()); // первый выдавший значение побеждает, остальные отписываются

race(this.api.load(), timer(5000).pipe(map(() => { throw new Error('timeout'); })));
```

## Операторные версии

Внутри `pipe` есть версии с суффиксом `With`: `combineLatestWith`, `mergeWith`, `concatWith`, `zipWith`, `raceWith`.

```ts
this.items$.pipe(combineLatestWith(this.filter$), map(([items, filter]) => applyFilter(items, filter)));
```

## Сводная таблица

| Оператор | Выдаёт | Завершается |
| --- | --- | --- |
| `combineLatest` | при любом новом значении (после первого от всех) | когда завершились все |
| `forkJoin` | один раз — последние значения | когда завершились все |
| `zip` | при наличии N-го значения у каждого | когда завершился любой (и буфер исчерпан) |
| `withLatestFrom` | только по значению основного потока | с основным |
| `merge` | каждое значение каждого | когда завершились все |
| `concat` | значения по очереди потоков | после последнего |
| `race` | значения первого «заговорившего» | вместе с победителем |

> [!INTERVIEW]
> «Чем combineLatest отличается от forkJoin?» — `forkJoin` ждёт завершения всех источников и выдаёт их последние значения один раз — аналог `Promise.all` для HTTP-запросов; с бесконечными потоками не работает. `combineLatest` выдаёт массив последних значений при каждом новом значении любого источника (после того как каждый выдал хотя бы одно) и подходит для производного состояния из нескольких живых потоков.

## Коротко

- `combineLatest` — живое производное состояние; нужен первый сигнал от каждого источника.
- `forkJoin` — параллельные запросы, один результат после завершения всех.
- `withLatestFrom` — действие + текущее состояние.
- `merge` — несколько источников одного события; `concat` — по очереди.
- `race` — первый ответивший; `zip` — попарно, используется редко.
