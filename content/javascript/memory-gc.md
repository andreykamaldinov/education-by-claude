В JavaScript память управляется автоматически: вы создаёте объекты, а сборщик мусора (GC) освобождает те, что больше не нужны. «Не нужны» в терминах GC означает **недостижимы**. Утечка памяти — это объект, который логически уже не нужен, но всё ещё достижим.

## Достижимость

**Корни** (roots) — то, что считается живым всегда: глобальный объект, текущий стек вызовов (локальные переменные выполняющихся функций), активные замыкания, обработчики, зарегистрированные в браузере. Объект жив, если до него можно дойти по ссылкам от корня.

```js
let user = { name: 'Анна' }; // объект достижим через переменную user
let admin = user; // две ссылки
user = null; // объект всё ещё достижим через admin
admin = null; // ссылок нет — объект станет мусором
```

## Mark-and-sweep

Современные движки используют алгоритм **mark-and-sweep** и его улучшения:

1. **Mark** — обойти граф от корней и пометить все достижимые объекты.
2. **Sweep** — освободить всё непомеченное.

Поэтому циклические ссылки не проблема: два объекта, ссылающиеся друг на друга, но недостижимые от корней, будут удалены. (Старый алгоритм подсчёта ссылок на циклах «тёк».)

### Поколения в V8

V8 делит кучу на **молодое поколение** (новые объекты, частые быстрые сборки — Scavenger) и **старое поколение** (объекты, пережившие несколько сборок, — Mark-Compact, работает реже и инкрементально/параллельно). Большинство объектов умирают молодыми, поэтому такая схема эффективна.

> [!NOTE]
> GC запускается сам, когда считает нужным. Вызвать его из кода нельзя (кроме флага `--expose-gc` в Node.js). Паузы GC могут вызывать «подёргивания» анимаций, если создавать много временных объектов в горячих циклах.

## Типичные утечки во фронтенде

### 1. Забытые подписки и обработчики

```ts
@Component({ /* ... */ })
export class ChartComponent implements OnInit {
  ngOnInit() {
    window.addEventListener('resize', this.redraw); // window держит ссылку на компонент навсегда
    interval(1000).subscribe(() => this.tick()); // таймер живёт после уничтожения компонента
  }
}
```

Исправление в Angular:

```ts
export class ChartComponent {
  constructor() {
    const destroyRef = inject(DestroyRef);

    const onResize = () => this.redraw();
    window.addEventListener('resize', onResize);
    destroyRef.onDestroy(() => window.removeEventListener('resize', onResize));

    interval(1000).pipe(takeUntilDestroyed()).subscribe(() => this.tick());
  }
}
```

Ещё удобнее — `@HostListener('window:resize')` или `host: { '(window:resize)': 'redraw()' }`: Angular сам снимет слушатель.

### 2. Отсоединённые DOM-узлы

```js
const cache = [];
function render() {
  const row = document.createElement('div');
  table.appendChild(row);
  cache.push(row); // после table.innerHTML = '' узел удалён из DOM, но жив в массиве
}
```

В Chrome DevTools такие узлы видны в heap snapshot с пометкой **Detached**.

### 3. Растущие кеши и глобальные коллекции

`Map` или массив на уровне модуля, куда только добавляют, — классическая утечка. Ограничивайте размер (LRU) или используйте слабые ссылки.

### 4. Замыкания

Таймер или обработчик держит замыкание, а замыкание — всё окружение, включая большие данные (см. урок [о замыканиях](/tracks/javascript/closures)).

### 5. shareReplay без refCount

`shareReplay(1)` без `refCount: true` держит подписку на источник даже после того, как все подписчики ушли. Подробнее — в уроке [share и shareReplay](/tracks/rxjs/multicasting).

## Слабые ссылки: WeakMap, WeakSet, WeakRef

`WeakMap` держит ключи **слабо**: если на объект-ключ больше нет других ссылок, запись исчезнет вместе с ним.

```js
const metadata = new WeakMap();

function track(element) {
  metadata.set(element, { clicks: 0, createdAt: Date.now() });
}
// Когда element удалят из DOM и забудут, запись в metadata тоже будет собрана.
```

Ограничения: ключи — только объекты (и незарегистрированные символы), коллекцию нельзя перебрать и нельзя узнать размер — иначе результат зависел бы от момента сборки мусора.

`WeakRef` и `FinalizationRegistry` дают ещё более низкоуровневый контроль:

```js
const ref = new WeakRef(bigObject);
const value = ref.deref(); // объект или undefined, если уже собран

const registry = new FinalizationRegistry((key) => console.log(`${key} собран`));
registry.register(bigObject, 'bigObject');
```

> [!WARNING]
> Не стройте логику приложения на `FinalizationRegistry`: момент вызова колбэка не гарантирован, а может и не наступить вовсе. Это инструмент для освобождения внешних ресурсов «на всякий случай», а не для бизнес-логики.

## Как искать утечки

1. **Chrome DevTools → Memory → Heap snapshot.** Сделайте снимок, выполните действие (открыть и закрыть страницу) несколько раз, сделайте второй снимок, выберите режим **Comparison** и ищите растущие конструкторы — например, ваши компоненты.
2. **Allocation instrumentation on timeline** — показывает, какие объекты выделяются и не освобождаются.
3. **Performance monitor** — график JS heap size и числа DOM-узлов. «Пила», которая не возвращается к базе, — признак утечки.
4. Поле **Retainers** в снимке показывает цепочку ссылок, которая удерживает объект, — обычно она и указывает на виновника.

## Коротко

- GC освобождает недостижимые объекты; утечка — ненужный, но достижимый объект.
- Mark-and-sweep справляется с циклами; V8 использует поколения.
- Главные источники утечек: подписки, слушатели, таймеры, отсоединённый DOM, неограниченные кеши.
- `WeakMap`/`WeakSet` для метаданных к объектам без продления их жизни.
- Ищите утечки сравнением heap snapshot до и после повторяющегося действия.
