JavaScript в браузере выполняется в одном потоке. При этом страница одновременно ждёт ответы сервера, таймеры, клики и анимации. Магию обеспечивает **event loop** — цикл событий, который решает, какой код и в каком порядке запускать. Вопрос «в каком порядке выведутся логи» задают почти на каждом собеседовании.

## Составные части

- **Call stack** — стек вызовов. Здесь выполняется синхронный код. Пока стек не пуст, ничего другого не происходит.
- **Web API** (в Node.js — libuv) — то, что работает вне JS-потока: таймеры, сеть, DOM-события, `fetch`.
- **Очередь задач (macrotask / task queue)** — колбэки `setTimeout`, `setInterval`, события ввода, `MessageChannel`, завершение загрузки скрипта.
- **Очередь микрозадач (microtask queue)** — колбэки промисов (`then`, `catch`, `finally`, продолжение после `await`), `queueMicrotask`, `MutationObserver`.
- **Рендеринг** — `requestAnimationFrame`, пересчёт стилей, layout, paint.

## Алгоритм одного «оборота»

```text
┌──────────────────────────────────────────────┐
│ 1. Взять ОДНУ задачу из очереди задач         │
│    и выполнить её до опустошения стека        │
│ 2. Выполнить ВСЕ микрозадачи                  │
│    (включая добавленные во время выполнения)  │
│ 3. Если пора рисовать кадр:                   │
│    rAF-колбэки → стили → layout → paint       │
│ 4. Повторить                                  │
└──────────────────────────────────────────────┘
```

Ключевое: после каждой макрозадачи очередь микрозадач опустошается **полностью**. Поэтому промисы всегда «обгоняют» таймеры.

## Классический пример

```js
console.log('1: синхронно');

setTimeout(() => console.log('2: таймер'), 0);

Promise.resolve()
  .then(() => console.log('3: микрозадача'))
  .then(() => console.log('4: ещё микрозадача'));

queueMicrotask(() => console.log('5: queueMicrotask'));

console.log('6: синхронно');
```

Вывод: `1, 6, 3, 5, 4, 2`.

1. Скрипт целиком — первая макрозадача: выводятся `1` и `6`, регистрируются таймер и микрозадачи.
2. Стек пуст — выполняются микрозадачи по порядку постановки: `3`, `5`. Колбэк `3` ставит в очередь следующий `then` — `4`, он тоже выполняется в этом же проходе.
3. Только потом очередь задач отдаёт таймер: `2`.

## async/await с точки зрения event loop

`await` разбивает функцию: всё до `await` выполняется синхронно, всё после — как микрозадача, когда промис разрешится.

```js
async function run() {
  console.log('A');
  await null;
  console.log('B');
}

console.log('1');
run();
console.log('2');
// 1, A, 2, B
```

> [!INTERVIEW]
> Расширенная задача:
> ```js
> setTimeout(() => console.log('timeout'));
> (async () => {
>   console.log('async start');
>   await Promise.resolve();
>   console.log('after await');
> })();
> new Promise((resolve) => {
>   console.log('executor');
>   resolve();
> }).then(() => console.log('then'));
> console.log('sync end');
> ```
> Ответ: `async start, executor, sync end, after await, then, timeout`. Executor промиса выполняется синхронно; продолжение после `await` и `then` — микрозадачи в порядке постановки; таймер — макрозадача.

## setTimeout(fn, 0) не значит «сейчас»

- Минимальная задержка в браузере — около 0–4 мс (после пяти вложенных таймеров — не меньше 4 мс).
- Таймер гарантирует «не раньше чем», а не «ровно через». Если стек занят тяжёлым кодом 200 мс, колбэк выполнится через 200 мс.
- Неактивные вкладки браузеры троттлят: таймеры могут срабатывать раз в секунду и реже.

## Голодание: бесконечные микрозадачи

Так как микрозадачи выполняются все до одной, рекурсивная постановка микрозадач блокирует рендер и ввод навсегда:

```js
function starve() {
  Promise.resolve().then(starve); // страница зависнет
}
```

А рекурсивный `setTimeout` — нет: между задачами браузер успевает рисовать и обрабатывать клики.

## requestAnimationFrame

`rAF` вызывается перед отрисовкой следующего кадра (обычно 60 раз в секунду, на 120 Гц экранах — 120). Это правильное место для анимаций и чтения/записи геометрии:

```js
function animate(timestamp) {
  box.style.transform = `translateX(${(timestamp / 10) % 300}px)`;
  requestAnimationFrame(animate);
}
requestAnimationFrame(animate);
```

## Длинные задачи и отзывчивость

Любая задача дольше 50 мс считается **long task**: пока она идёт, страница не реагирует на ввод, а метрика INP (Interaction to Next Paint) ухудшается. Способы разбить работу:

```js
// Отдать управление браузеру между порциями
async function processAll(items) {
  for (const [index, item] of items.entries()) {
    process(item);
    if (index % 500 === 0) {
      await scheduler.yield?.() ?? new Promise((r) => setTimeout(r, 0));
    }
  }
}
```

Тяжёлые вычисления лучше вынести в Web Worker — отдельный поток со своим event loop (так устроена песочница практики на этой платформе).

## Event loop и Angular

- **zone.js** перехватывает `setTimeout`, промисы, события и после завершения задачи запускает change detection. Поэтому в «классическом» Angular данные обновляются после любого асинхронного действия.
- В **zoneless**-режиме (по умолчанию с Angular 21) проверку планируют сигналы, события шаблона, `async` pipe и `markForCheck()`; планировщик использует микро- и макрозадачи, чтобы схлопнуть несколько изменений в один проход.
- `afterNextRender` выполняет код после того, как Angular обновил DOM, — аналог «после рендера» для работы с геометрией.

Подробнее: [Zone.js](/tracks/angular/zone-js) и [Zoneless Angular](/tracks/angular/zoneless).

## Node.js: отличия

В Node.js event loop состоит из фаз (timers → pending callbacks → poll → check → close). Дополнительно есть `process.nextTick` — его очередь выполняется **раньше** промисов, и `setImmediate` — фаза check, после I/O.

```js
setTimeout(() => console.log('timeout'), 0);
setImmediate(() => console.log('immediate'));
process.nextTick(() => console.log('nextTick'));
Promise.resolve().then(() => console.log('promise'));
// nextTick, promise, затем timeout/immediate (порядок между ними зависит от контекста)
```

## Коротко

- Один поток, один стек; асинхронность обеспечивают очереди.
- После каждой макрозадачи выполняются все микрозадачи, затем возможен рендер.
- Промисы и `await` — микрозадачи, `setTimeout` и события — макрозадачи.
- Executor `new Promise` выполняется синхронно.
- Долгие задачи (>50 мс) блокируют ввод — дробите работу или выносите в воркер.
