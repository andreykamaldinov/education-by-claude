Область видимости отвечает на вопрос «где эта переменная доступна». Hoisting (всплытие) — на вопрос «когда она появляется». Вместе они объясняют, почему `var` ведёт себя странно, а `let` и `const` бросают `ReferenceError` до объявления.

## Виды областей видимости

- **Глобальная** — переменные верхнего уровня скрипта. В модуле (ESM) верхний уровень — это область модуля, а не глобальная.
- **Функциональная** — создаётся при каждом вызове функции. Здесь живут `var` и параметры.
- **Блочная** — любой `{ ... }`: тело `if`, `for`, `try`, просто блок. Здесь живут `let`, `const` и `class`.

```js
function demo() {
  if (true) {
    var a = 1; // функциональная область
    let b = 2; // блочная область
    const c = 3; // блочная область
  }
  console.log(a); // 1
  console.log(b); // ReferenceError: b is not defined
}
```

JavaScript использует **лексическую** (статическую) область видимости: доступность переменной определяется местом в исходном коде, а не тем, откуда функцию вызвали.

```js
const x = 'глобальная';

function outer() {
  const x = 'outer';
  return inner();
}

function inner() {
  return x; // ищется там, где inner ОБЪЯВЛЕНА
}

outer(); // 'глобальная'
```

## Как работает hoisting

Перед выполнением кода движок проходит по нему и регистрирует все объявления в соответствующем окружении. Это фаза **создания**. Затем код выполняется построчно.

| Объявление | Регистрируется | Значение до строки объявления |
| --- | --- | --- |
| `var x` | в функции | `undefined` |
| `let x`, `const x` | в блоке | недоступна (TDZ) |
| `function f() {}` | в функции/блоке | готовая функция |
| `class C {}` | в блоке | недоступна (TDZ) |
| `const f = () => {}` | как `const` | недоступна (TDZ) |

```js
console.log(a); // undefined
var a = 5;

sayHi(); // 'Привет' — function declaration поднимается целиком
function sayHi() {
  console.log('Привет');
}

greet(); // TypeError: greet is not a function (var поднят как undefined)
var greet = function () {};
```

## Временная мёртвая зона (TDZ)

`let`, `const` и `class` тоже «всплывают» — движок знает о них с начала блока. Но до строки объявления они находятся в TDZ, и любое обращение бросает `ReferenceError`.

```js
let value = 'внешняя';

{
  console.log(value); // ReferenceError: Cannot access 'value' before initialization
  let value = 'внутренняя';
}
```

Если бы `let` не поднимался, `console.log` вывел бы `'внешняя'`. Ошибка доказывает: внутренняя `value` уже зарегистрирована в блоке и затеняет внешнюю, просто ещё не инициализирована.

> [!INTERVIEW]
> «Поднимаются ли `let` и `const`?» — Да, поднимаются, но не инициализируются. Между началом блока и строкой объявления переменная находится во временной мёртвой зоне, обращение к ней бросает `ReferenceError`. `var` поднимается и сразу инициализируется `undefined`.

TDZ работает даже с `typeof`, который обычно безопасен:

```js
typeof notDeclared; // 'undefined'
typeof later; // ReferenceError
let later = 1;
```

## Почему `var` считается устаревшим

1. **Нет блочной области** — переменная «протекает» из `if` и `for`.
2. **Повторное объявление разрешено** — `var x = 1; var x = 2;` не ошибка, легко затереть данные.
3. **Создаёт свойство глобального объекта** на верхнем уровне скрипта: `var foo` → `window.foo`.
4. **Всплытие с `undefined`** маскирует ошибки порядка инициализации.

```js
for (var i = 0; i < 3; i++) {}
console.log(i); // 3 — переменная цикла доступна снаружи
```

## `const` не означает неизменяемость

`const` запрещает **переприсваивание переменной**, но не изменение объекта, на который она указывает:

```js
const config = { retries: 3 };
config.retries = 5; // можно
config = {}; // TypeError: Assignment to constant variable

const frozen = Object.freeze({ retries: 3 });
frozen.retries = 5; // молча игнорируется (в strict mode — TypeError)
```

> [!TIP]
> Правило по умолчанию: всё объявляйте через `const`, `let` — только если переменную действительно нужно переприсвоить. `var` не используйте.

## Затенение (shadowing)

Внутренняя переменная с тем же именем перекрывает внешнюю:

```js
const status = 'idle';

function load() {
  const status = 'loading'; // затеняет внешнюю
  return status;
}
```

Затенение законно, но запутывает при чтении. ESLint-правило `no-shadow` помогает его ловить.

## Strict mode

В модулях ES и в классах strict mode включён всегда. Он превращает тихие ошибки в явные:

- присваивание необъявленной переменной бросает `ReferenceError` вместо создания глобальной;
- `this` в обычной функции, вызванной без контекста, — `undefined`, а не `window`;
- запрещены дублирующиеся параметры и `with`.

```js
'use strict';
undeclared = 10; // ReferenceError
```

## Коротко

- Область видимости лексическая: решает место в коде, а не место вызова.
- `var` — функциональная область, поднимается с `undefined`.
- `let`/`const`/`class` — блочная область, поднимаются, но до объявления в TDZ.
- Function declaration поднимается целиком, function expression — нет.
- `const` защищает переменную, а не содержимое объекта.
