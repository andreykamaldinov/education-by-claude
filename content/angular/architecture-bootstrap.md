Angular — платформа для построения приложений: компилятор, система компонентов, внедрение зависимостей, роутер, формы, HTTP, SSR и CLI. Чтобы уверенно в ней работать, полезно понимать, что происходит между `ng serve` и первым кадром на экране.

## Строительные блоки

| Блок | Назначение |
| --- | --- |
| **Компонент** | класс + шаблон + стили; единица UI |
| **Директива** | поведение, добавляемое к существующему элементу |
| **Пайп** | преобразование значения в шаблоне |
| **Сервис** | класс с логикой и состоянием, доступный через DI |
| **Инжектор** | контейнер, создающий и хранящий зависимости |
| **Роутер** | сопоставляет URL с компонентами |

## Standalone вместо NgModule

С Angular 14 появились standalone-компоненты, с версии 19 они стали поведением **по умолчанию** (флаг `standalone: true` больше не пишут). Компонент сам объявляет, что использует:

```ts
@Component({
  selector: 'app-user-list',
  imports: [RouterLink, UserCard, DatePipe], // зависимости шаблона
  template: `
    @for (user of users(); track user.id) {
      <app-user-card [user]="user" />
    }
  `,
})
export class UserList {
  readonly users = input.required<User[]>();
}
```

NgModule по-прежнему поддерживается, но для нового кода не нужен. Плюсы standalone: меньше шаблонного кода, явные зависимости, лучше tree-shaking и ленивая загрузка на уровне отдельного компонента.

## Точка входа

```ts
// main.ts
bootstrapApplication(App, appConfig).catch((err) => console.error(err));

// app.config.ts
export const appConfig: ApplicationConfig = {
  providers: [
    provideBrowserGlobalErrorListeners(),
    provideRouter(routes, withComponentInputBinding()),
    provideHttpClient(withFetch(), withInterceptors([authInterceptor])),
  ],
};
```

Что делает `bootstrapApplication`:

1. Создаёт **платформенный инжектор** (сервисы уровня браузера) и **корневой инжектор окружения** приложения из `providers`.
2. Запускает инициализаторы (`provideAppInitializer`) и ждёт их, если они асинхронные.
3. Находит в `index.html` элемент с селектором корневого компонента (`<app-root>`), создаёт компонент и его view.
4. Подключает механизм обнаружения изменений и выполняет первый проход: шаблон рендерится в DOM.

> [!NOTE]
> С Angular 21 новые приложения создаются **без zone.js** (zoneless), а с Angular 22 стратегия `OnPush` используется по умолчанию для всех компонентов. Эти две вещи сильно меняют модель «как Angular узнаёт об изменениях» — см. раздел Change Detection.

## Компилятор: AOT и Ivy

Браузер не понимает шаблоны Angular. Их нужно превратить в JavaScript-инструкции. Этим занимается компилятор Angular (`@angular/compiler-cli`), встроенный в сборку CLI.

**AOT (Ahead-of-Time)** — компиляция при сборке. Стандарт с Angular 9 и единственный режим для production. JIT (компиляция в браузере) остался для отдельных сценариев вроде некоторых тестов.

**Ivy** — движок рендеринга и формат скомпилированного кода. Шаблон превращается в функцию с двумя режимами: создание DOM и обновление биндингов.

```ts
@Component({
  selector: 'app-greeting',
  template: `<h1>Привет, {{ name() }}</h1>`,
})
export class Greeting {
  readonly name = input('гость');
}
```

Упрощённо компилируется в:

```js
static ɵcmp = ɵɵdefineComponent({
  type: Greeting,
  selectors: [['app-greeting']],
  inputs: { name: [1, 'name'] },
  decls: 2,
  vars: 1,
  template: function (rf, ctx) {
    if (rf & 1) {            // режим создания
      ɵɵelementStart(0, 'h1');
      ɵɵtext(1);
      ɵɵelementEnd();
    }
    if (rf & 2) {            // режим обновления
      ɵɵadvance();
      ɵɵtextInterpolate1('Привет, ', ctx.name(), '');
    }
  },
});
```

Плюсы Ivy-подхода:

- **Локальность** — каждый компонент компилируется независимо, зная только свои зависимости. Это ускоряет инкрементальную сборку.
- **Tree-shaking рантайма** — инструкции (`ɵɵelementStart`, `ɵɵlistener`) — обычные функции. Если шаблоны не используют `@defer` или пайпы, их код не попадёт в бандл.
- **Проверка типов шаблонов** — компилятор генерирует TypeScript-код для проверки (type-check blocks), поэтому `strictTemplates` ловит ошибки в HTML.

## Структура view

Каждый экземпляр компонента имеет **LView** — массив, хранящий DOM-узлы, значения биндингов, дочерние view и контекст. Статическая информация шаблона (какие узлы, какие директивы) хранится один раз на тип компонента в **TView**. Обновление шаблона — это проход по LView с сравнением новых значений биндингов со старыми.

```text
Приложение
└── AppComponent (LView)
    ├── HeaderComponent (LView)
    └── RouterOutlet
        └── UserListComponent (LView)
            ├── @for → embedded views (по одному на элемент)
            └── UserCard × N (LView)
```

Это дерево view — то самое дерево, которое обходит change detection.

## Жизненный цикл приложения в целом

```text
ng build / ng serve
  → компилятор Angular (шаблоны → инструкции, проверка типов)
  → esbuild (TS → JS, бандлинг, минификация)
  → index.html + чанки

Браузер
  → загрузка main.js
  → bootstrapApplication
  → создание инжекторов и корневого компонента
  → первый рендер
  → события / сигналы / HTTP → планирование change detection → обновление DOM
```

> [!INTERVIEW]
> «Что такое Ivy и чем AOT лучше JIT?» — Ivy — текущий движок компиляции и рендеринга Angular: шаблоны превращаются в функции с инструкциями создания и обновления DOM, каждый компонент компилируется локально, неиспользуемые части рантайма вырезаются tree-shaking'ом. AOT компилирует шаблоны при сборке: в браузер не нужно грузить компилятор, ошибки шаблонов ловятся заранее, старт быстрее, а отсутствие `eval`-подобной компиляции упрощает строгую CSP.

## Коротко

- Standalone-компоненты — стандарт; NgModule не нужен для нового кода.
- `bootstrapApplication` создаёт инжекторы, корневой компонент и выполняет первый рендер.
- AOT-компилятор превращает шаблоны в инструкции Ivy; проверяет типы в шаблонах.
- Каждый компонент — LView; приложение — дерево view.
- Angular 21+: zoneless по умолчанию; Angular 22: `OnPush` по умолчанию.
