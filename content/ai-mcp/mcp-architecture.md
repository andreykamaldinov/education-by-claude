MCP описывает, кто с кем общается, какие возможности предоставляет сервер и каким транспортом передаются сообщения. Разберём участников, примитивы и эволюцию протокола до текущей stateless-версии.

## Участники

```text
┌──────────────── Host (AI-приложение: IDE, Claude, агент) ────────────────┐
│  LLM ◀──▶ логика приложения                                              │
│              │                                                           │
│      ┌───────┴───────┬───────────────┐                                   │
│      ▼               ▼               ▼                                   │
│  MCP Client 1    MCP Client 2    MCP Client 3                             │
└──────┼───────────────┼───────────────┼───────────────────────────────────┘
       ▼               ▼               ▼
  MCP Server        MCP Server       MCP Server
  (Angular CLI,     (GitHub,         (ваша база
   stdio, локально)  удалённо, HTTP)  данных)
```

- **Host** — приложение, с которым работает пользователь. Управляет моделью, решает, какие серверы подключены, и спрашивает согласие пользователя на действия.
- **Client** — компонент внутри host-а, поддерживающий соединение с **одним** сервером.
- **Server** — программа, предоставляющая возможности: инструменты, данные, шаблоны.

## Примитивы сервера

| Примитив | Кто управляет | Что это | Пример |
| --- | --- | --- | --- |
| **Tools** | модель | функции с JSON Schema аргументов; модель решает, когда вызвать | `create_issue`, `run_tests`, `search_documentation` |
| **Resources** | приложение | данные с URI, которые можно прочитать и добавить в контекст | `file:///src/app.ts`, `db://schema/orders` |
| **Prompts** | пользователь | шаблоны сообщений, выбираемые в интерфейсе (например, slash-команды) | `/review-pr`, `/explain-error` |

Описание инструмента:

```json
{
  "name": "search_lessons",
  "title": "Поиск по урокам",
  "description": "Ищет уроки платформы по ключевым словам. Используй, когда пользователь спрашивает о теме из JS, TS, Angular или RxJS.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "Ключевые слова, например «switchMap отмена»" },
      "limit": { "type": "integer", "minimum": 1, "maximum": 20, "default": 5 }
    },
    "required": ["query"]
  },
  "annotations": { "readOnlyHint": true, "openWorldHint": false }
}
```

- `description` пишется **для модели** — от его качества зависит, будет ли инструмент вызван правильно.
- `annotations` (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) — подсказки host-у, например, нужно ли спрашивать подтверждение.
- Инструмент может вернуть `structuredContent` по `outputSchema` — типизированный результат вместо свободного текста.

## Возможности клиента

Сервер тоже может обращаться к клиенту:

- **Elicitation** — запросить у пользователя недостающие данные («Какой проект использовать?»).
- **Sampling** — попросить модель host-а сгенерировать текст (в ревизии 2026-07-28 объявлен устаревшим).
- **Roots** — узнать, с какими папками работает пользователь (тоже устаревает).

## Протокол сообщений: JSON-RPC 2.0

```json
// запрос клиента
{ "jsonrpc": "2.0", "id": 7, "method": "tools/call",
  "params": { "name": "search_lessons", "arguments": { "query": "switchMap" } } }

// ответ сервера
{ "jsonrpc": "2.0", "id": 7,
  "result": { "content": [{ "type": "text", "text": "Найдено 2 урока: …" }], "isError": false } }
```

Основные методы: `tools/list`, `tools/call`, `resources/list`, `resources/read`, `prompts/list`, `prompts/get`, а также уведомления об изменении списков.

> [!NOTE]
> Ошибки выполнения инструмента (например, «задача не найдена») возвращаются как результат с `isError: true` — так модель увидит ошибку и сможет исправиться. Ошибки протокола (неизвестный метод, неверные параметры) — как JSON-RPC `error`.

## Транспорты

| Транспорт | Как | Когда |
| --- | --- | --- |
| **stdio** | host запускает сервер как дочерний процесс, сообщения — построчно через stdin/stdout | локальные серверы: CLI-инструменты, файловая система, Angular CLI MCP |
| **Streamable HTTP** | POST-запросы на один endpoint, ответ — JSON или поток (SSE) | удалённые серверы, SaaS, корпоративные развёртывания |
| HTTP+SSE (старый) | отдельный SSE-канал и POST | устарел, заменён Streamable HTTP |

Для удалённых серверов авторизация построена на **OAuth 2.1**: MCP-сервер выступает ресурс-сервером, клиент получает токен у сервера авторизации (PKCE обязателен).

## Эволюция: от сессий к stateless (ревизия 2026-07-28)

| | Ревизии 2024–2025 | Ревизия 2026-07-28 |
| --- | --- | --- |
| Начало работы | handshake `initialize` / `initialized`, согласование версии и возможностей | нет handshake; возможности — через `server/discover` |
| Сессия | заголовок `Mcp-Session-Id`, состояние на сервере | **нет сессий**: каждый запрос самодостаточен, версия протокола — в `_meta` запроса |
| Масштабирование | «липкие» сессии на балансировщике | любой экземпляр сервера обслуживает любой запрос |
| Маршрутизация | парсинг тела | заголовки `Mcp-Method`, `Mcp-Name` |
| Многошаговые запросы | sampling/elicitation в рамках сессии | Multi Round-Trip Requests: сервер возвращает `InputRequiredResult`, клиент повторяет запрос с `requestState` |
| Подписки | GET-поток, `resources/subscribe` | `subscriptions/listen` |
| Новое | — | MCP Apps (HTML-интерфейсы в изолированном iframe), задачи (tasks) как расширение, JSON Schema 2020-12, W3C Trace Context |

SDK v2 поддерживают обе «эпохи»: серверы могут обслуживать и старых клиентов (с `initialize`), и новых.

> [!INTERVIEW]
> «Из чего состоит архитектура MCP?» — Host — AI-приложение с моделью; внутри него клиенты, каждый подключён к одному MCP-серверу. Сервер предоставляет tools (действия, которые вызывает модель), resources (данные по URI, которые добавляет приложение) и prompts (шаблоны, которые выбирает пользователь). Сообщения — JSON-RPC 2.0, транспорт — stdio для локальных серверов или Streamable HTTP для удалённых с OAuth 2.1. С ревизии 2026-07-28 протокол stateless: нет handshake и сессий, возможности узнаются через `server/discover`.

## Коротко

- Host → клиенты (по одному на сервер) → серверы.
- Tools — для модели, resources — для приложения, prompts — для пользователя.
- JSON-RPC 2.0; stdio локально, Streamable HTTP удалённо, OAuth 2.1 для авторизации.
- Описания инструментов пишутся для модели; аннотации помогают host-у решать о подтверждении.
- Ревизия 2026-07-28: stateless, `server/discover`, без сессий, MCP Apps.
