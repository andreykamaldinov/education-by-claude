Angular CLI содержит собственный MCP-сервер. Подключив его к AI-ассистенту в IDE, вы даёте модели актуальные знания об Angular (а не о версии из её обучающих данных), доступ к структуре вашего workspace и возможность запускать сборку и тесты.

## Запуск

```bash
ng mcp            # выводит инструкции по подключению
npx -y @angular/cli mcp   # команда, которую запускает AI-клиент
```

Сервер работает через stdio: AI-клиент сам запускает его как дочерний процесс.

### Подключение

```json
// .vscode/mcp.json — VS Code / Copilot
{
  "servers": {
    "angular-cli": {
      "command": "npx",
      "args": ["-y", "@angular/cli", "mcp"]
    }
  }
}
```

Для Cursor, JetBrains, Claude Code, Gemini CLI и других клиентов формат почти такой же — блок `mcpServers` с той же командой. Файл `.vscode/mcp.json` можно коммитить: в `.gitignore` нового Angular-проекта он уже разрешён.

## Инструменты сервера

Набор инструментов зависит от версии CLI. В актуальных версиях:

| Инструмент | Что делает |
| --- | --- |
| `get_best_practices` | отдаёт актуальное руководство по лучшим практикам Angular (standalone, сигналы, control flow, `inject()`, OnPush) — модель пишет код в современном стиле |
| `search_documentation` | поиск по официальной документации angular.dev для текущей версии |
| `list_projects` | список приложений и библиотек workspace с их путями и настройками |
| `onpush_zoneless_migration` | анализирует код и предлагает пошаговый план перехода на OnPush и zoneless |
| `ai_tutor` | интерактивный режим обучения Angular |
| `run_target` | запуск целей `angular.json` (build, test, lint) |
| `devserver_start` / `devserver_stop` / `devserver_wait_for_build` | управление dev-сервером, чтобы ассистент мог проверить, что приложение собирается |

Флаги сервера ограничивают его возможности:

```bash
npx @angular/cli mcp --read-only          # только инструменты без побочных эффектов
npx @angular/cli mcp --local-only         # только инструменты без доступа в сеть
npx @angular/cli mcp --experimental-tool <name>   # включить экспериментальный инструмент
```

`--read-only` и `--local-only` работают через аннотации инструментов (`readOnlyHint`, `openWorldHint`) — тот же механизм, что разобран в уроке [Архитектура MCP](/tracks/ai-mcp/mcp-architecture).

## Зачем это нужно

Языковые модели обучены на огромном количестве старого Angular-кода: NgModules, `*ngIf`, конструкторная инъекция, `@Input()` и zone.js. Без подсказок ассистент генерирует именно такой код. MCP-сервер CLI решает проблему:

- модель получает **актуальные best practices** вашей версии Angular;
- ищет ответы в **документации вашей версии**, а не по памяти;
- видит **реальную структуру** workspace;
- может **проверить** результат: собрать проект, запустить тесты.

## Правила для ассистента в проекте

Дополнительно к MCP полезно положить в репозиторий файл с правилами — его читают AI-инструменты:

| Инструмент | Файл |
| --- | --- |
| общий стандарт многих агентов | `AGENTS.md` |
| Claude Code | `CLAUDE.md` |
| GitHub Copilot | `.github/copilot-instructions.md` |
| Cursor | `.cursor/rules/*.mdc` |

Новые проекты Angular CLI может создавать с готовыми файлами правил (`ng new --ai-config`). Пример содержимого:

```markdown
# Правила проекта

- Angular 22, standalone-компоненты, zoneless, OnPush по умолчанию.
- Состояние — сигналы; производное — computed; effect только для внешних побочных эффектов.
- Inputs/outputs — input(), output(), model(). Внедрение — inject().
- Шаблоны — @if/@for/@switch, @for всегда с track по id.
- Стили — Tailwind с семантическими токенами из styles.css.
- Тесты — Vitest, `ng test`. Новый код покрывается тестами.
- Никаких any и as-приведений; типы через type, без enum.
```

## llms.txt

Angular публикует документацию в формате для языковых моделей: `angular.dev/llms.txt` (краткая карта) и `llms-full.txt` (полный текст). Их можно подключать как контекст к любому ассистенту, если MCP недоступен.

## AI в самом приложении

Отдельная тема — использование AI в Angular-приложениях: стриминг ответов модели (`httpResource` и `fetch`-стриминг, см. [WebSocket, SSE и long polling](/tracks/web/realtime)), Genkit/Firebase AI Logic, и экспериментальная поддержка **WebMCP** в Signal Forms (`provideExperimentalWebMcpForms`): формы приложения могут объявлять себя инструментами для AI-агента в браузере.

> [!TIP]
> Относитесь к ассистенту как к младшему коллеге: давайте контекст (MCP, правила), проверяйте результат (тесты, ревью), не принимайте код, который не понимаете. Особенно — код, связанный с безопасностью.

> [!INTERVIEW]
> «Как AI-инструменты помогают в Angular-разработке?» — Angular CLI предоставляет MCP-сервер (`ng mcp`), который даёт ассистенту в IDE актуальные best practices и поиск по документации текущей версии, сведения о проектах workspace, запуск сборки и тестов и инструмент планирования миграции на OnPush и zoneless. Дополнительно в репозитории держат файлы правил (`AGENTS.md` и аналоги), чтобы ассистент генерировал код в стиле проекта, а не по устаревшим образцам из обучающих данных.

## Коротко

- `npx -y @angular/cli mcp` — MCP-сервер CLI для AI-клиентов (stdio).
- Инструменты: best practices, поиск по документации, проекты, сборка/тесты, миграция на zoneless.
- `--read-only` и `--local-only` ограничивают возможности сервера.
- Правила проекта — в `AGENTS.md`/`CLAUDE.md`/`copilot-instructions.md`.
- `llms.txt` — документация Angular в формате для моделей.
