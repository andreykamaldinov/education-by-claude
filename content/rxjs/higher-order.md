Операторы высшего порядка — `switchMap`, `mergeMap`, `concatMap`, `exhaustMap` — самая важная тема RxJS и самый частый вопрос на собеседовании. Все четыре превращают каждое значение во **внутренний Observable** и подписываются на него. Различаются они одним: **что делать, если пришло новое значение, а предыдущий внутренний поток ещё не завершился**.

## Проблема: поток потоков

```ts
search$.pipe(map((query) => this.api.search(query)));
// Observable<Observable<Result[]>> — подписчик получит объекты Observable, а не результаты
```

Вложенный `subscribe` — плохое решение: нет отмены, нет контроля порядка, утечки.

```ts
// Антипаттерн
search$.subscribe((query) => {
  this.api.search(query).subscribe((results) => (this.results = results));
});
```

Операторы высшего порядка подписываются на внутренние потоки сами и «сплющивают» их значения в один поток.

## switchMap: отменить предыдущий

```text
query:   --a-----b--c-----------|
inner:     a1-a2   b1  c1--c2--|
switchMap: --a1-a2--b1-c1--c2--|     (b отменён, когда пришёл c)
```

При новом значении **отписывается** от предыдущего внутреннего потока и подписывается на новый.

```ts
this.searchControl.valueChanges.pipe(
  debounceTime(300),
  distinctUntilChanged(),
  switchMap((query) => this.api.search(query)),
);
```

**Когда**: важен только результат для последнего значения — поиск, автокомплит, загрузка данных при смене параметра маршрута, фильтры.

Отписка от HTTP-потока отменяет запрос, поэтому устаревшие ответы не перезапишут новые (нет «гонки»).

> [!WARNING]
> Не используйте `switchMap` для операций записи: сохранение, оплата, удаление. Если пользователь быстро кликнет дважды, первый запрос будет отменён на клиенте, но сервер мог его уже выполнить — а вы не узнаете результат.

## mergeMap: всё параллельно

```text
id:       --1--2--3------------|
inner:      1a----1b
               2a-2b
                  3a----3b
mergeMap: --1a-2a-3a1b2b--3b--|   (порядок по времени ответа)
```

Подписывается на каждый внутренний поток сразу, все работают параллельно, значения перемешиваются по мере прихода.

```ts
// Загрузить детали для каждого id, не более 4 запросов одновременно
from(ids).pipe(mergeMap((id) => this.api.details(id), 4));

// Независимые действия: каждая загрузка файла — сама по себе
files$.pipe(mergeMap((file) => this.uploader.upload(file)));
```

**Когда**: операции независимы и порядок не важен. Второй аргумент `concurrency` ограничивает параллельность.

## concatMap: по очереди

```text
action:    --1--2--3----------------|
inner:       1a--1b|
                   2a--2b|
                         3a--3b|
concatMap: --1a--1b-2a--2b-3a--3b|
```

Подписывается на следующий внутренний поток только после **завершения** предыдущего. Новые значения ждут в очереди.

```ts
// Сохранения должны идти строго в порядке изменений
changes$.pipe(concatMap((change) => this.api.save(change)));

// Анимации шагов по очереди
steps$.pipe(concatMap((step) => this.animate(step)));
```

**Когда**: важен порядок, операции зависят друг от друга, запись в одну сущность.

> [!NOTE]
> Если внутренний поток никогда не завершается (например, `interval`), `concatMap` никогда не перейдёт к следующему значению — очередь будет расти.

## exhaustMap: игнорировать, пока занят

```text
click:      --c--c--c-------c----|
inner:        r-----r|      r--r|
exhaustMap: --r-----r-------r--r|   (клики во время запроса проигнорированы)
```

Пока внутренний поток активен, новые значения **отбрасываются**.

```ts
// Отправка формы: повторные клики во время запроса ничего не делают
submit$.pipe(exhaustMap(() => this.api.submitOrder(this.form.getRawValue())));

// Вход, обновление токена, «потяни, чтобы обновить»
refresh$.pipe(exhaustMap(() => this.api.reload()));
```

**Когда**: повторное действие во время выполнения бессмысленно или опасно.

## Шпаргалка

| Оператор | Новое значение, пока внутренний поток активен | Типичная задача |
| --- | --- | --- |
| `switchMap` | отменить старый, запустить новый | поиск, загрузка по параметру |
| `mergeMap` | запустить параллельно | независимые операции |
| `concatMap` | поставить в очередь | сохранения по порядку |
| `exhaustMap` | проигнорировать | отправка формы, логин |

Мнемоника по поведению: **switch** — переключиться, **merge** — смешать, **concat** — склеить последовательно, **exhaust** — «я занят, не мешай».

## Обработка ошибок внутри

Ошибка во внутреннем потоке убивает **внешний** поток: после первой ошибки поиск перестанет работать навсегда.

```ts
// Плохо: одна ошибка сети — и поиск мёртв
query$.pipe(switchMap((q) => this.api.search(q)));

// Хорошо: ловим ошибку внутри, внешний поток продолжает жить
query$.pipe(
  switchMap((q) =>
    this.api.search(q).pipe(
      catchError(() => {
        this.error.set('Поиск временно недоступен');
        return of([]);
      }),
    ),
  ),
);
```

## Индекс и проектор

Все четыре оператора передают индекс значения: `switchMap((value, index) => ...)`. Устаревший второй аргумент `resultSelector` удалён — комбинируйте результаты через `map` внутри:

```ts
userId$.pipe(switchMap((id) => this.api.orders(id).pipe(map((orders) => ({ id, orders })))));
```

> [!INTERVIEW]
> «Чем отличаются switchMap, mergeMap, concatMap и exhaustMap?» — Все превращают значение во внутренний Observable и сплющивают результат. Разница — поведение при новом значении, пока предыдущий внутренний поток активен: `switchMap` отменяет предыдущий (поиск, загрузка по параметру), `mergeMap` запускает параллельно (независимые операции, можно ограничить concurrency), `concatMap` ставит в очередь и сохраняет порядок (последовательные сохранения), `exhaustMap` игнорирует новые значения до завершения текущего (отправка формы, логин).

## Коротко

- Вложенный `subscribe` заменяется оператором высшего порядка.
- `switchMap` — последний важен, предыдущий отменяется; не для записи.
- `mergeMap` — параллельно, с ограничением concurrency.
- `concatMap` — очередь, порядок сохраняется.
- `exhaustMap` — игнорировать повторные действия во время выполнения.
- Ловите ошибки внутри, иначе внешний поток завершится.
