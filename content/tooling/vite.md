Vite (2020, Эван Ю) изменил представление о скорости разработки: dev-сервер стартует за миллисекунды независимо от размера проекта, а изменения появляются мгновенно. Секрет — в разработке Vite **не собирает бандл**, а отдаёт браузеру нативные ES-модули. **esbuild** — сверхбыстрый сборщик на Go, на котором Vite изначально строил свои быстрые операции.

## Два режима Vite

```text
Разработка:  браузер ──import──▶ dev-сервер Vite ──трансформирует по запросу──▶ отдельные ES-модули
Production:  исходники ──▶ Rolldown (раньше Rollup) ──▶ оптимизированные чанки
```

### Dev: нативные ESM

```html
<script type="module" src="/src/main.ts"></script>
```

Браузер сам запрашивает `main.ts`, видит `import './app'`, запрашивает `app.ts` и так далее. Vite перехватывает каждый запрос и **трансформирует только этот файл** (TS → JS) на лету. Неиспользуемые на текущей странице модули вообще не обрабатываются.

Поэтому время старта не зависит от размера проекта: Webpack сначала собирает всё, Vite — ничего.

### Pre-bundling зависимостей

Зависимости из `node_modules` обрабатываются иначе:

- многие пакеты поставляются в CommonJS — их нужно превратить в ESM;
- пакет вроде `lodash-es` состоит из сотен файлов — сотни запросов браузера замедлили бы загрузку.

Поэтому при первом старте Vite **один раз** собирает зависимости в несколько ESM-файлов (раньше — esbuild, в Vite 8 — Rolldown) и кеширует их с долгоживущим HTTP-кешем.

### HMR

При изменении файла Vite отправляет по WebSocket сообщение браузеру, тот перезапрашивает **только изменённый модуль**. Скорость HMR не зависит от размера приложения. В Angular HMR работает для стилей и шаблонов компонентов без потери состояния.

### Production

Нативные ESM в продакшене неэффективны (водопады запросов, нет tree-shaking и минификации на уровне всего графа), поэтому для сборки Vite использует полноценный бандлер. Исторически это был Rollup (с esbuild для трансформаций и минификации). С Vite 8 и сборщик, и pre-bundling работают на **Rolldown** — Rust-бандлере с API, совместимым с Rollup, что устранило расхождения между dev и production.

## esbuild

Сборщик, написанный на Go (Эван Уоллес, 2020):

- в десятки–сотни раз быстрее JS-сборщиков: компилируемый язык, параллельная обработка на всех ядрах, минимум проходов по AST;
- умеет транспилировать TS/JSX, бандлить, минифицировать, делать tree-shaking и code splitting для ESM;
- **не проверяет типы** — только удаляет их (поэтому Angular CLI отдельно запускает компилятор TypeScript/Angular для проверки).

```js
import { build } from 'esbuild';

await build({
  entryPoints: ['src/main.ts'],
  bundle: true,
  splitting: true,
  format: 'esm',
  outdir: 'dist',
  minify: true,
  sourcemap: true,
  target: ['es2022'],
});
```

## Конфигурация Vite

```ts
// vite.config.ts (в проектах на Vite напрямую — React, Vue, Svelte)
import { defineConfig } from 'vite';

export default defineConfig({
  server: {
    port: 5173,
    proxy: { '/api': 'http://localhost:3000' },
  },
  build: {
    target: 'es2022',
    sourcemap: true,
  },
  plugins: [],
});
```

В Angular-проектах `vite.config.ts` не используется: Angular CLI встраивает Vite как dev-сервер и конфигурируется через `angular.json`.

## Экосистема Vite

- **Vitest** — тест-раннер, использующий конвейер трансформаций Vite (стандарт `ng test` в новых Angular-проектах).
- **Vite-плагины** совместимы с плагинами Rollup.
- На Vite построены Nuxt, SvelteKit, Astro, Analog (мета-фреймворк для Angular), Remix/React Router и многие другие.

> [!INTERVIEW]
> «Почему dev-сервер Vite стартует быстрее Webpack?» — Webpack перед стартом собирает бандл всего приложения. Vite в разработке не бандлит исходники: браузер загружает нативные ES-модули, а Vite трансформирует каждый файл по запросу, только когда он нужен. Зависимости из `node_modules` один раз пред-собираются в ESM и кешируются. HMR обновляет только изменённый модуль, поэтому скорость не зависит от размера проекта. Для production Vite использует полноценный бандлер (Rollup, с Vite 8 — Rolldown).

## Коротко

- Vite в dev отдаёт нативные ES-модули и трансформирует файлы по запросу.
- Зависимости пред-собираются и кешируются.
- HMR — точечное обновление модулей по WebSocket.
- Production-сборка — полноценный бандлер (Rolldown в Vite 8).
- esbuild — сверхбыстрый сборщик на Go, не проверяет типы.
