Выбор сборщика — компромисс между скоростью, гибкостью, экосистемой плагинов и стоимостью миграции. Для Angular-проектов выбор в основном сделан за вас (Angular CLI), но понимание ландшафта нужно для монорепозиториев, библиотек, микрофронтендов и общего кругозора.

## Сравнение

| | Webpack | Rspack | Vite | esbuild | Rolldown | Turbopack |
| --- | --- | --- | --- | --- | --- | --- |
| Язык | JavaScript | Rust | JS-оболочка над нативными инструментами | Go | Rust | Rust |
| Скорость | низкая на больших проектах | высокая | dev — мгновенный, build — высокая | очень высокая | очень высокая | высокая |
| Dev-подход | бандл в памяти | бандл в памяти | нативные ESM по запросу | — (низкоуровневый) | (через Vite) | инкрементальные бандлы |
| Экосистема | огромная, зрелая | совместима с большинством плагинов Webpack | плагины Rollup/Vite | ограниченная | совместима с Rollup API | привязан к Next.js |
| Module Federation | встроено (v5) | встроено (MF 2.0) | через плагины | через Native Federation | через плагины | нет |
| Где используется | легаси, сложные кастомные сборки | миграция с Webpack с ускорением | большинство новых проектов | как ядро других инструментов, Angular CLI | Vite 8 | Next.js |

## Как выбирать

### Новый Angular-проект

Angular CLI (`@angular/build:application`): esbuild + Vite. Без вариантов и без необходимости.

### Nx-монорепозиторий с Angular

Тот же builder через executors Nx; для микрофронтендов — Native Federation или Module Federation (Nx поддерживает варианты на Webpack и Rspack).

### Легаси на Webpack с кастомной конфигурацией

1. Если проект Angular — сначала попробовать миграцию на `application` builder.
2. Если кастомизация Webpack критична (сложные плагины, Module Federation v1) — рассмотреть **Rspack**: совместимый API, значительное ускорение, минимальные изменения конфигурации.

### Библиотека (npm-пакет)

- Angular-библиотеки — `ng-packagr` (Angular Package Format, частичная компиляция).
- Обычные TS-библиотеки — `tsup`/`tsdown` (обёртки над esbuild/Rolldown), Rollup, `unbuild` или просто `tsc`.

### Приложение на React/Vue/Svelte

Vite — стандарт де-факто (или мета-фреймворк поверх него), для Next.js — Turbopack.

## Ключевые тренды

- **Нативные языки**: инструменты переписываются на Rust и Go — в 10–100 раз быстрее JS-реализаций.
- **Унификация**: Rolldown объединяет dev и production в Vite одним бандлером; Oxc (Rust) — парсер, линтер (oxlint), трансформер, минификатор и форматтер в одном наборе. В Angular CLI уже используется oxc-parser.
- **Отказ от бандлинга в dev** (Vite) против инкрементальных бандлов (Turbopack) — два подхода к быстрой разработке.
- **ESM повсюду**: CommonJS постепенно уходит из экосистемы, что упрощает инструменты.

## Сборщик — не бутылочное горлышко?

Иногда долгая сборка вызвана не бандлером:

- **проверка типов** (`tsc` / компилятор Angular) — на больших проектах занимает основную часть времени; помогает инкрементальность и разделение на библиотеки;
- **линтинг** в том же процессе;
- **тяжёлые PostCSS-плагины** и неоптимальные глобы Tailwind;
- **отсутствие кеша** в CI (Nx/Turborepo cache, кеш `.angular/cache`).

> [!INTERVIEW]
> «Что выбрать для нового проекта: Webpack или Vite?» — Для нового проекта обычно Vite или инструмент фреймворка, построенный на современных бандлерах: быстрый dev-сервер, простая конфигурация, большая экосистема. В Angular — встроенный builder на esbuild и Vite. Webpack оправдан для легаси со сложной кастомной конфигурацией или Webpack-специфичными возможностями; при желании ускориться без переписывания конфигурации — Rspack.

## Коротко

- Angular-проект — Angular CLI (esbuild + Vite); выбор уже сделан.
- Легаси на Webpack — миграция на application builder или Rspack.
- Библиотеки — ng-packagr для Angular, tsup/Rollup для обычных TS-пакетов.
- Тренд — инструменты на Rust/Go, Rolldown и Oxc, ESM повсюду.
- Долгая сборка часто упирается в проверку типов и отсутствие кеша, а не в бандлер.
