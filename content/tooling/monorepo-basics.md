Монорепозиторий — один репозиторий, содержащий несколько проектов: приложения, библиотеки, бэкенд, инструменты. Это не «монолит» — проекты остаются отдельными, но живут вместе, с общими инструментами и возможностью атомарных изменений.

## Monorepo против polyrepo

```text
Polyrepo                                  Monorepo
repo: shop-web                            repo: shop
repo: shop-admin                            apps/web
repo: ui-kit (npm-пакет)                    apps/admin
repo: api-client (npm-пакет)                apps/api
repo: shop-api                              libs/ui-kit
                                            libs/api-client
                                            libs/shared/utils
```

| | Polyrepo | Monorepo |
| --- | --- | --- |
| Изменение в библиотеке и потребителях | публикация пакета, обновление версий в каждом репо | один коммит / PR |
| Версии зависимостей | могут разъехаться | единые (обычно один `package.json`) |
| Переиспользование кода | через публикацию пакетов | прямой импорт |
| Видимость | каждая команда видит своё | весь код виден, легко найти использования |
| Права и изоляция | естественные | нужно настраивать (CODEOWNERS, правила границ) |
| CI | простой на репо | нужны умные инструменты (affected, кеш), иначе медленно |
| Инструменты | стандартные | Nx, Turborepo, Bazel, pnpm/npm workspaces |

## Плюсы монорепозитория

- **Атомарные изменения**: поменяли API библиотеки и всех её потребителей в одном PR — нет «окна несовместимости».
- **Единые версии**: Angular, RxJS, TypeScript одной версии во всех проектах; обновление — один раз (`nx migrate`).
- **Переиспользование без публикации**: общая UI-библиотека, утилиты, типы API — просто импорт.
- **Единые стандарты**: линтер, форматтер, конфиги TypeScript, генераторы кода.
- **Рефакторинг по всему коду** с поддержкой IDE.
- **Общие типы фронтенда и бэкенда** (если бэкенд на TypeScript) — контракт API проверяется компилятором.

## Минусы и как с ними справляются

| Проблема | Решение |
| --- | --- |
| CI собирает и тестирует всё на каждый PR | `affected`-команды: только затронутые проекты |
| Повторная работа | вычислительный кеш (локальный и удалённый) |
| Всё связано со всем | правила границ модулей, теги, линтер |
| Масштаб git-репозитория | sparse checkout, shallow clone |
| Ответственность за код | CODEOWNERS по папкам |
| Единая версия зависимостей — обновлять всех сразу | автоматические миграции (`nx migrate`), постепенность |

## Инструменты

### Менеджеры пакетов: workspaces

```json
// package.json корня (npm/yarn/pnpm workspaces)
{
  "workspaces": ["apps/*", "libs/*"]
}
```

Связывают локальные пакеты между собой, устанавливают зависимости одним деревом. Базовый уровень — без графа задач и кеша.

### Turborepo

Оркестратор задач для JS-монорепозиториев поверх workspaces: граф задач (`build` зависит от `^build` зависимостей), кеш, параллельный запуск. Минималистичный и простой.

### Nx

Полноценная платформа монорепозитория: граф проектов на основе анализа кода, `affected`, локальный и удалённый кеш, распределённое выполнение задач в CI, генераторы, автоматические миграции, правила границ модулей, плагины для Angular, React, Node.js, NestJS и других. Исторически создан выходцами из команды Angular и — стандарт для крупных Angular-проектов. Подробно — [Nx: граф проекта, affected и кеш](/tracks/tooling/nx).

### Bazel

Сборочная система Google для гигантских полиглотных монорепозиториев: герметичные, воспроизводимые сборки. Мощный, но сложный; во фронтенде используется редко.

## Монорепозиторий и микрофронтенды

Это ортогональные вещи: микрофронтенды могут жить и в монорепозитории (удобно: общие библиотеки, единые версии Angular — меньше проблем с shared-зависимостями), и в отдельных репозиториях (максимальная независимость команд). Nx поддерживает генерацию host/remote-приложений с федерацией.

> [!INTERVIEW]
> «В чём плюсы и минусы монорепозитория?» — Плюсы: атомарные изменения библиотеки и её потребителей в одном PR, единые версии зависимостей, переиспользование кода без публикации пакетов, единые стандарты и инструменты, лёгкий рефакторинг. Минусы: без специальных инструментов CI собирает всё и медленно, есть риск хаотичных зависимостей между проектами, сложнее разграничивать доступ. Решения — Nx/Turborepo с affected-командами и кешем, правила границ модулей, CODEOWNERS.

## Коротко

- Monorepo — много проектов в одном репозитории; не путать с монолитом.
- Атомарные изменения, единые версии, переиспользование без публикации.
- Масштабируется только с affected, кешем и правилами границ.
- Инструменты: workspaces → Turborepo → Nx → Bazel.
- Для Angular-экосистемы стандарт — Nx.
