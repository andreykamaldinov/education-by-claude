HTTP — протокол, на котором держится общение фронтенда с сервером. Понимание методов, статусов, заголовков кеширования и различий версий протокола напрямую влияет на скорость приложения и на то, как вы проектируете работу с API.

## Запрос и ответ

```http
GET /api/products?page=2 HTTP/1.1
Host: shop.example.com
Accept: application/json
Authorization: Bearer eyJhbGciOi...
If-None-Match: "a1b2c3"

HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Cache-Control: private, max-age=60
ETag: "d4e5f6"

{"items": [...], "total": 120}
```

## Методы

| Метод | Назначение | Безопасный | Идемпотентный | Тело |
| --- | --- | --- | --- | --- |
| `GET` | получить ресурс | да | да | нет |
| `HEAD` | только заголовки | да | да | нет |
| `POST` | создать / выполнить действие | нет | **нет** | да |
| `PUT` | заменить ресурс целиком | нет | да | да |
| `PATCH` | частично изменить | нет | не гарантируется | да |
| `DELETE` | удалить | нет | да | обычно нет |
| `OPTIONS` | узнать возможности (CORS preflight) | да | да | нет |

- **Безопасный** — не меняет состояние на сервере.
- **Идемпотентный** — повтор запроса даёт тот же результат, что и один вызов. Поэтому автоматические повторы (`retry`) допустимы для GET/PUT/DELETE, но опасны для POST. Для безопасного повтора POST используют заголовок `Idempotency-Key`.

## Коды статусов

| Класс | Примеры |
| --- | --- |
| **1xx** информационные | `101 Switching Protocols` (WebSocket), `103 Early Hints` |
| **2xx** успех | `200 OK`, `201 Created`, `202 Accepted`, `204 No Content` |
| **3xx** перенаправление | `301` (навсегда), `302`/`307` (временно), `304 Not Modified` |
| **4xx** ошибка клиента | `400 Bad Request`, `401 Unauthorized` (не аутентифицирован), `403 Forbidden` (нет прав), `404`, `409 Conflict`, `422 Unprocessable Content`, `429 Too Many Requests` |
| **5xx** ошибка сервера | `500`, `502 Bad Gateway`, `503 Service Unavailable`, `504 Gateway Timeout` |

> [!TIP]
> `401` — «кто вы?» (нужно войти или обновить токен), `403` — «я знаю, кто вы, но нельзя». Интерсептор должен обрабатывать их по-разному: на `401` — обновить токен или отправить на логин, на `403` — показать «нет доступа».

## Кеширование

### Cache-Control

```http
Cache-Control: public, max-age=31536000, immutable   # статика с хешем в имени (main-a1b2.js)
Cache-Control: no-cache                              # можно хранить, но перед использованием проверить
Cache-Control: no-store                              # не хранить вообще (персональные данные)
Cache-Control: private, max-age=60                   # только браузер (не CDN), 60 секунд
Cache-Control: max-age=60, stale-while-revalidate=300
```

| Директива | Смысл |
| --- | --- |
| `max-age=N` | свежий N секунд, без запроса к серверу |
| `no-cache` | хранить можно, но всегда валидировать |
| `no-store` | не хранить |
| `public` / `private` | можно ли кешировать промежуточным прокси/CDN |
| `immutable` | не валидировать даже при перезагрузке |
| `stale-while-revalidate` | отдать устаревшее и обновить в фоне |

Стратегия для Angular-приложения:

- `index.html` — `no-cache` (иначе пользователи не получат новую версию);
- `main-[hash].js`, `chunk-[hash].js`, шрифты — `max-age=31536000, immutable` (Angular CLI добавляет хеши в имена при `outputHashing: all`);
- API — по смыслу данных, часто `no-cache` или короткий `max-age` + ETag.

### Условные запросы

```http
# Первый ответ
ETag: "v42"
Last-Modified: Wed, 28 Oct 2026 10:00:00 GMT

# Повторный запрос браузера
If-None-Match: "v42"
If-Modified-Since: Wed, 28 Oct 2026 10:00:00 GMT

# Ответ, если не изменилось — без тела
HTTP/1.1 304 Not Modified
```

## HTTP/1.1 → HTTP/2 → HTTP/3

| | HTTP/1.1 | HTTP/2 | HTTP/3 |
| --- | --- | --- | --- |
| Транспорт | TCP | TCP | QUIC поверх UDP |
| Формат | текст | бинарные фреймы | бинарные фреймы |
| Параллельность | 1 запрос на соединение (6 соединений на домен) | мультиплексирование потоков в одном соединении | то же, без блокировки на уровне транспорта |
| Сжатие заголовков | нет | HPACK | QPACK |
| Head-of-line blocking | на уровне HTTP | на уровне TCP (потеря пакета тормозит все потоки) | нет — потоки независимы |
| Установка соединения | TCP + TLS | TCP + TLS | 1-RTT, 0-RTT при повторе, миграция соединения при смене сети |

Практические следствия:

- Приёмы эпохи HTTP/1.1 — склейка всего в один файл, спрайты, шардинг доменов — с HTTP/2 больше не нужны или вредны. Много небольших чанков (code splitting) загружаются эффективно.
- HTTP/3 особенно выигрывает на мобильных сетях с потерями пакетов.
- `103 Early Hints` позволяет начать загрузку CSS и шрифтов, пока сервер ещё генерирует HTML (полезно для SSR).

## Сжатие

```http
Accept-Encoding: gzip, br, zstd
Content-Encoding: br
```

Brotli сжимает текст (JS, CSS, HTML, JSON) на 15–25% лучше gzip. Включается на сервере или CDN; статические файлы лучше сжимать заранее при сборке.

## Полезные заголовки для фронтенда

| Заголовок | Зачем |
| --- | --- |
| `Content-Type` | формат тела (`application/json`) |
| `Accept-Language` | язык пользователя |
| `Authorization` | токен |
| `Retry-After` | когда повторить после `429`/`503` |
| `Location` | URL созданного ресурса (с `201`) или редиректа |
| `X-Request-Id` / `traceparent` | сквозная трассировка запроса до бэкенда |

> [!INTERVIEW]
> «Чем HTTP/2 лучше HTTP/1.1 и что даёт HTTP/3?» — HTTP/2 мультиплексирует много запросов в одном TCP-соединении бинарными фреймами и сжимает заголовки, поэтому браузеру не нужно открывать по 6 соединений и склеивать ресурсы. Но при потере TCP-пакета блокируются все потоки. HTTP/3 работает поверх QUIC (UDP): потоки независимы, установка соединения быстрее (вплоть до 0-RTT), соединение переживает смену сети.

## Коротко

- Методы различаются безопасностью и идемпотентностью — это определяет, можно ли повторять.
- 401 — не аутентифицирован, 403 — нет прав, 304 — используйте кеш.
- `index.html` — `no-cache`, хешированные бандлы — `immutable` на год.
- ETag/`If-None-Match` экономят трафик.
- HTTP/2 — мультиплексирование, HTTP/3 — QUIC без блокировки потоков.
